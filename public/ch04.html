04概念

生成AIとAIエージェントの違い

この章のゴール
「答えるAI（生成AI）」と「動くAI（AIエージェント）」の違いを理解し、エージェントを支える RAG・MCP・Function Calling・マルチエージェント の役割を説明できるようになる。

4-1答えるAIと動くAI

一言でいうと生成AIは質問に答えるだけ。AIエージェントは目的達成のために自分で考え・調べ・ツールを使い、仕事を実行するAI。

初心者は「ChatGPT＝AIエージェント」と思いがちだが、両者は別物。生成AIは「質問→回答」で終わる。AIエージェントは「依頼→計画→ツール利用→実行→確認」まで進める。Agentは英語で「代理人・代行者」。旅行代理店が代わりに予約するように、人間の代わりに仕事を進める。

生成AI（答えるAI）

  • 「メールを書いて」→ 本文を書く
  • 送信ボタンは人間が押す
  • 「ホテル候補はこちら」で終わる
  • 質問→回答で完結

AIエージェント（動くAI）

  • 宛先・添付を確認し、実際に送信
  • 予算確認→検索→比較→予約まで実行
  • カレンダー登録・完了報告まで
  • 仕事そのものを実行
あなた依頼
LLM計画
ツール利用
実行・確認
完了
図 4-1　生成AIは「LLM→回答」で終わるが、エージェントは途中の処理が大幅に増える
✕ 誤解ChatGPT＝AIエージェントで、何でも自動でできる
○ 正しくはChatGPTはLLM中心のサービス。エージェントはLLM＋ツール＋計画・実行機能を組み合わせたシステム。ツールや権限が無ければ操作はできない
ここだけ覚える
  • 生成AI＝答えるAI／AIエージェント＝仕事を実行するAI
  • LLMはエージェントの「頭脳」（中の一部）
  • AIは「答えるAI」から「働くパートナー」へ進化している

4-2AIエージェントの基本構造

一言でいうとほとんどのAIエージェントは「目標を理解し、計画し、調べ、実行し、確認し、必要ならやり直す」という共通の流れで動く。

人間が仕事をするときの流れと同じ。OpenAI Agents SDK・LangGraph・CrewAI・AutoGen など多くのフレームワークがこの構造を共有している。8つの要素を順に回す。

Goal何を達成するか
Planning手順へ分解
Reasoning最適な方法を考える
Memory情報を覚える
Tool Use外部ツール利用
Action実際に実行
Observation結果を確認
Reflection失敗を分析し改善
完了問題があればPlanningへ戻る
図 4-2　AIエージェントの基本ループ（失敗時はReflectionからPlanningへ戻る）
要素役割
Goal「何を達成したいか」という最終目的。曖昧だとAIは動けない
Planning大きな仕事を小さな手順へ分解（Task Decomposition）
Reasoning条件を比較し最適な方法を考える（推論モデルが活躍）
Memory必要な情報を覚える。短期／長期／外部（RAG・DB）がある
Tool Useメール・検索・カレンダーなど外部ツールを呼ぶ
ActionAPI等を通じて実際に操作を実行する
Observation実行結果を確認。確認しないと「できました」と嘘をつく恐れ
Reflection失敗の原因を考え計画を修正し再挑戦。成功率が上がる
最も重要なのは「LLM選び」ではなく「設計」

初心者は「賢いLLMに変えれば賢くなる」と考えがちだが、実際は Goal・Planning・Memory・Tool・Reflection の設計が品質を大きく左右する。AIエージェントは「仕事の進め方」をソフトウェアとして再現した仕組み、いわば優秀な新入社員に近い。

4-3Browser AgentとComputer Use

一言でいうとAIに「Webブラウザを使う力」を与えたのがBrowser Agent、「PC全体を画面で操作する力」を与えたのがComputer Use。

Browser Agentは単なるWeb検索と違い、目的を理解し、検索語を考え、ページを読み、複数サイトを比較し、出典付きでレポートまで作る ── AIに「Web調査員」の役割を持たせる仕組み。Computer Useはさらに広く、画面を見て（スクリーンショット／UI要素／OCR）、マウス・キーボードで人間のようにアプリやファイルを操作する。AIに「目」と「手」を与える技術。

項目Browser AgentComputer Use
操作対象WebブラウザPC全体（OS・アプリ・ファイル）
代表作業Web検索・比較・フォーム入力Excel・PDF・業務システム入力
難易度中高
リスクWeb誤操作・規約違反PC全体の誤操作
RPAとの違い

従来のRPAは「決まった画面操作」を自動化するだけ。Computer UseはLLMの判断力を加えるため、APIの無い古い業務システムでも柔軟に操作できる。ただし画面変更に弱く、実行速度も遅くなりがち。

注意すべき限界

ログインが必要なサイト・CAPTCHA・動的サイト・自動操作禁止の規約には対応できない（突破すべきでない）。誤クリック・誤入力（10,000円→100,000円など）・情報漏えいの恐れがあるため、送信・予約・購入・削除は人間承認を必須にする。

4-4RAG ── 調べてから答える

一言でいうとRAG（検索拡張生成）は、必要な情報を検索（Retrieval）してから回答を生成（Generation）する仕組み。AIが「分からないことを調べてから答える」。

LLMはネット上の一般知識は持つが、あなたの会社の規程・マニュアル・契約書は知らない。文書が更新されるたびに学習し直す（Fine-tuning）のは非現実的。そこで、回答前に社内文書を読ませるのがRAG。新人が就業規則を見ながら答えるのと同じで、「ズル」ではなく「資料を確認して仕事をする」こと。

質問
Embedding意味を数字へ
ベクトルDB検索Retrieval
関連文書をLLMへContext Injection
回答生成
図 4-4　RAGの流れ。ベクトルDBは「旅費」から「交通費・宿泊費」まで意味の近い文書を探せる
項目Fine-tuningRAG
モデル更新必要（知識を組み込む）不要（検索するだけ）
最新・社内情報苦手・更新が大変得意（文書を更新するだけ）
コスト高い比較的低い
主な用途話し方・専門能力の改善最新・個別情報の参照
✕ 誤解RAGを使えばハルシネーション（誤情報）はなくなる
○ 正しくはRAGは根拠を提供するが、LLMが誤って解釈する可能性は残る。出典を表示し、分からない時は「分からない」と返す設計が必要

4-5MCPとFunction Calling ── ツールへつなぐ

一言でいうとFunction CallingはLLMが「いまツールを呼ぶべきだ」と判断する仕組み。MCPはAIと外部ツールを共通ルールでつなぐ「USB-C」のような標準規格。

LLM単体ではメール送信もカレンダー登録もできない。Function Callingは、AIが文脈から「ここでは calendar.create_event を呼ぶべき」と判断し、考えるだけのAIを「行動するAI」へ変える仕組み。

MCP（Model Context Protocol）は2024年に Anthropic が提唱したオープンなプロトコルで、OpenAIなど多くのツールでも採用が進む。従来はSlack API・GitHub API…とサービスごとに個別実装が必要だったが、MCPに対応すれば共通ルールで接続できる。

Host（AIアプリ全体）Claude Desktop・ChatGPT・VS Code・Cursor …
MCP Client（Serverへ接続して利用する側）
MCP Server（ツール・データを提供）→ Slack / GitHub / Google Drive / 社内DB / Salesforce
図 4-5　MCPの全体構成。Host内でClientが動き、Server経由で各サービスへつながる
用語意味
APIサービス同士を接続する仕組み（サービスごとに違う）
MCPAIがAPIやツールを統一的に使うための共通プロトコル（APIの上にある）
ToolAIが使える「機能」（検索・メール送信など）。MCPは「接続ルール」
MCP Serverツール・データを提供する側（GitHub MCP Server 等）
MCP Client / HostServerを利用する側／AIアプリ全体を動かす土台
権限とセキュリティの設計が不可欠

削除・送信・更新までできると誤操作が危険。読み取り専用から導入し、更新・削除系は人間承認、Toolごとに最小権限、監査ログを残す。MCPがあってもセキュリティ設計は不要にならない。

4-6マルチエージェント

一言でいうと複数のAIエージェントが役割を分担し、協力して1つの仕事を完成させる仕組み。いわば「AI版の組織設計」。

1つのAIに全部やらせるより、専門AI（調査・分析・作成・レビューなど）へ分けた方が品質が上がることがある。会社で営業・開発・法務・経理が分かれているのと同じ。代表的な3つの構成がある。

  • リーダーAI（Supervisor）
    • 調査AI
    • 分析AI
    • 資料作成AI
    • レビューAI ── 統合して最終回答
図 4-6　Supervisor型のイメージ。リーダーAIが仕事を割り振り、結果を統合する
構成特徴実務利用
Supervisor型リーダーAIが複数AIへ仕事を割り振る。管理しやすい非常に多い
Team型リーダー無しでAI同士が対等に相談。柔軟だが通信コスト大一部
Specialist型税務AI・法務AIなど専門分野ごとに分担。専門性が高い多い
✕ 誤解AIを増やせば必ず性能が上がる
○ 正しくは役割分担が不適切だと通信コストと複雑さだけが増える。無限ループを防ぐため最大実行回数・タイムアウトを設定。小さな仕事はシングルエージェントで十分

4-7メリット・リスクと人間の役割

一言でいうとAIエージェントは強力だが万能ではない。導入ではメリットだけでなくリスクも理解し、人間との協調（Human in the Loop）を設計することが重要。

メリット

  • 仕事そのものを自動化できる
  • 24時間稼働、複数ツールを連携
  • 失敗から改善（Reflection）できる
  • 人間は判断・交渉に集中できる

デメリット

  • 誤った判断・行動の可能性
  • システムが複雑になり保守が難しい
  • LLM呼び出しが増えコスト増
  • エラーが連鎖する
リスク内容対策
誤操作誤ったメール送信や予約・削除人間の承認（Human in the Loop）
ハルシネーション誤情報に基づく行動RAG・出典確認
情報漏えい機密情報へのアクセス権限管理・アクセス制御
コスト増API・GPU利用料実行回数の最適化
無限ループ同じ処理を繰り返す最大実行回数・タイムアウト
AI下書き作成
人間確認・承認
AIが送信・実行
図 4-7　Human in the Loop ── 重要操作は人間が途中で確認する
人間が不要になるわけではない

契約・採用・医療・金融など、重要な判断や法的責任を伴う場面では最終判断は人間が行うべき。AIエージェントは「自動化」ではなく、状況を見て手段を選び修正する「半自律的な業務遂行」に近い。

★第4章まとめ

この章の要点
  • 生成AI＝「答えるAI」、AIエージェント＝「動くAI（仕事を実行）」
  • エージェントは Goal→Planning→…→Observation→Reflection のループで動く
  • RAGは検索してから答える（Fine-tuningと違い学習ではない）
  • MCPはAIと外部ツールをつなぐ共通プロトコル（Function Callingで呼び出す）
  • 重要操作はHuman in the Loopで人間が承認することが不可欠

理解度チェック
1生成AIとAIエージェントの最も大きな違いは？
  • A. 使うLLMの種類
  • B. 回答するだけか、仕事を実行するか
  • C. 日本語か英語か
  • D. 無料か有料か
正解：B　生成AIは「答えるAI」、エージェントは計画・ツール利用・実行まで行う「動くAI」。
2AIエージェントが結果を確認する工程はどれ？
  • A. Planning
  • B. Memory
  • C. Observation
  • D. Goal
正解：C　Observationで実行結果を確認する。確認しないと「できました」と誤報告する恐れがある。
3RAGの説明として正しいのは？
  • A. モデルを追加学習させる
  • B. 関連文書を検索してから回答する
  • C. ハルシネーションを完全になくす
  • D. ブラウザを操作する
正解：B　RAGは検索（Retrieval）してから生成（Generation）する仕組み。学習（Fine-tuning）ではない。
4MCPを一言で例えると？
  • A. AIのための「USB-C」（共通接続規格）
  • B. 新しいLLM
  • C. 検索エンジン
  • D. プログラミング言語
正解：A　MCPはAIと外部ツールを共通ルールでつなぐ標準規格。2024年にAnthropicが提唱。
5重要操作（送金・契約・送信）でとるべき設計は？
  • A. すべてAIに任せる
  • B. Human in the Loop（人間が承認）
  • C. 確認せず高速実行
  • D. ログを残さない
正解：B　取り消しにくい操作は人間が途中で確認・承認する設計が不可欠。
