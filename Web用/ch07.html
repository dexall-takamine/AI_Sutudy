第7章 エージェントを支える技術
07技術

エージェントを支える技術

この章のゴール
LLM単体ではできない「Web検索・社内資料の参照・PC操作・外部連携」を可能にする周辺技術 ── Browser Agent・Computer Use・MCP・RAG・Vector Database・Function Calling・マルチエージェント の役割と違いを説明できるようになる。
この章の項目
  1. Browser Agent
  2. Computer Use
  3. MCP（共通接続規格）
  4. RAG（検索してから回答）
  5. Vector Database
  6. Function Calling
  7. マルチエージェント
なぜこの章が必要か

LLMだけなら「東京の天気を教えて」と聞いても学習済み知識で答えようとする。Web検索・社内文書の参照・メール送信・予定登録といった仕事は、AIの外側にある技術を組み合わせて初めて実現できる。AIエージェント開発とは「LLMを賢くすること」ではなく周辺技術をどう組み合わせるかである。

7-1Browser Agent

一言でいうと人間の代わりにWebブラウザを操作し、情報を検索・取得・整理するAIエージェント。単なる検索エンジンではなく、実際にページを開いて読む。

LLMはリアルタイムでインターネットを見ているわけではない。「今日発表された最新ニュースを教えて」には答えられない。そこを補うのがBrowser Agent。人間が調査するときと同じ流れで動く。

  • ニュース収集・市場調査・競合分析
  • 価格比較・求人検索

苦手なこと

  • CAPTCHAの突破

ここだけ覚える
  • Browser Agentはブラウザを操作するAI
  • Web検索より高度な処理（巡回・比較・要約）を行う
  • 最新情報の取得が得意

7-2Computer Use

一言でいうと人間の代わりにPC画面を見て、クリック・入力・操作を行うAI技術。ブラウザ以外のExcel・Word・SAP・Salesforceなども操作できる。

Computer Useは GUI（Graphical User Interface＝画面上のボタンやアイコンをマウスで操作する仕組み）を認識しながら、人間と同じように操作する。

7-3MCP（Model Context Protocol）

一言でいうとAIと外部ツールを接続するための共通ルール（標準プロトコル）。USBが様々な機器を同じ規格で繋ぐように、MCPはAIとToolを繋ぐ共通規格。

AIエージェントはSlack・Gmail・GitHub・Notion・Google Drive・社内システムなど多様なToolを使う。接続方法がバラバラだと、AIを作るたびに書き換えが必要になる。MCPはこの問題を解決する。

ここだけ覚える
  • MCPはAI用の共通接続規格
  • Toolとの接続を標準化する（追加・再利用・保守が楽）
  • APIとは役割が異なる

7-4RAG（Retrieval-Augmented Generation）

一言でいうと必要な情報を検索してから、その情報を使って回答する仕組み。生成AIの弱点である「最新情報・社内情報を知らない」を補う。

「社内の旅費規程を教えて」と聞かれてもLLM単体では答えられない。RAGは Retrieval（検索）→ Augmented（情報追加）→ Generation（回答生成）の頭文字。

質問

ベクトル検索
関連文書を取得
LLMへ渡すContext Injection
回答
図 7-4　RAGは「検索→生成」の流れで回答する

文書はEmbeddingでベクトルへ変換され、意味の近い文書を検索できる。LLM単体が「推測」で答えるのに対し、RAGは社内文書を根拠にするためハルシネーション（もっともらしい嘘）を減らせる。

RAGFine-tuning
やること文書検索モデル再学習
更新簡単コストが高い
向き最新情報・社内文書話し方・専門性の定着
デメリット・注意点

検索品質に依存する／文書整備が必要／ベクトルDBの管理が必要／誤った文書を取得すると誤回答になる。

ここだけ覚える
  • RAGは検索してから回答する仕組み
  • EmbeddingとベクトルDBを利用する
  • Fine-tuningとは役割が異なる
  • 社内AIでは最も重要な技術の一つ

7-5Vector Database（ベクトルデータベース）

一言でいうと「文章の意味」を数値（ベクトル）として保存し、意味の近い情報を高速に検索するためのデータベース。RAGの検索先になる。

普通のDBは「完全一致」が得意（例：WHERE Name = '田中'）。だが質問「生成AIについて教えて」に対し、社内文書が「大規模言語モデルについて」と書かれていると、文字が一致せずヒットしない。Embeddingなら意味が近いので検索できる。

犬[0.18, -0.52, 0.76 …]
猫[0.16, -0.49, 0.81 …]
図 7-5a　意味が近い語はベクトルも近くなる（Embeddingで数百〜数千次元の数値に変換）
質問
Embedding
類似度（Similarity）検索
意味が近い文書
図 7-5b　「同じ言葉」ではなく「同じ意味」を検索する
通常のデータベースVector Database
入力名前・条件質問→Embedding

Pinecone／Weaviate／Milvus／Chroma／Qdrant／pgvector（PostgreSQL拡張）／Azure AI Search（ベクトル検索対応）。クラウド・オンプレなど用途に応じて使い分ける。

ここだけ覚える
  • Vector Databaseは意味検索のためのデータベース
  • Embeddingしたベクトルを保存する
  • RAGではほぼ必須の技術

7-6Function Calling

一言でいうとLLMが「必要な機能（Function）」を選び、外部システムやプログラムを呼び出す仕組み。Functionとはプログラムの関数やAPIを指す。

文章を書くだけでは仕事は終わらない。「明日の予定を教えて」にはカレンダーを、「メールを送って」にはメールシステムを操作する必要がある。人間がスマホのカレンダーを開くように、AIも必要なツールを呼び出す。

ユーザー
LLMFunctionを判断
Function呼び出し
結果取得→LLM
回答
図 7-6　Function Callingの流れ（例：予定確認→Google Calendar API→予定取得→回答）

内部的にはAPIを呼び出すことが多い。Function Callingは「何を呼ぶか」を決める役割、APIは「実際に通信する仕組み」。

Function CallingTool Calling（第6章）
意味Functionを呼び出す仕組みツール全体を利用する考え方
範囲API実行（技術的な機能）Browser・Python・DBなども含む（エージェント全体の行動）

つまりFunction CallingはTool Callingを実現するための重要な技術の一つ。利用例：Gmail送信／Google Calendar登録／Slack投稿／GitHub Issue作成／Salesforce更新。

ここだけ覚える
  • Function Callingは外部機能を呼び出す仕組み
  • LLMが必要なFunctionを選択する
  • APIやToolと組み合わせて利用される

7-7マルチエージェント（Multi-Agent）

一言でいうと複数のAIエージェントが役割分担しながら協力して仕事を進める仕組み。1つのAIで進める「シングルエージェント」の対概念。

企業では一人で仕事を進めることは少ない。営業提案書も営業・技術・法務・マネージャーが協力する。AIにも得意・不得意があり、専門分野ごとに分けた方が高品質な結果を得られる。

  • Supervisor（管理AI）── 仕事を振り分ける
    • 営業Agent
    • 技術Agent
    • 法務Agent

Supervisor型

中央の管理役が仕事を振り分ける

Team型

Specialist型

実務例：営業提案（営業→市場分析→技術→提案書→レビュー）／ソフトウェア開発（要件→設計→開発→テスト→レビュー）／カスタマーサポート（受付→FAQ→技術→回答）。

項目シングルマルチ

コスト比較的低い比較的高い
適した用途小規模なタスク大規模・複雑な業務
今後の主流へ

OpenAI・Anthropic・Google・Microsoftなど主要企業で、単一の巨大AIではなく役割分担を行うマルチエージェント構成の研究・開発が進む。複雑・長時間のタスクほど効果が大きい。

ここだけ覚える
  • マルチエージェントは複数のAIが協力して仕事を進める仕組み
  • Supervisor型・Team型・Specialist型が代表的
  • 複雑な業務ほど効果が大きく、将来の重要な設計パターン

理解度チェック
1Browser AgentとComputer Useの主な違いは？
  • A. どちらもWebブラウザ専用
  • B. Browser Agentはブラウザ操作、Computer UseはPC全体（Excel・SAP等）の操作
  • C. Computer Useは情報取得専用
  • D. 違いはない
正解：B　Browser AgentはWebブラウザ中心で情報取得が得意、Computer UseはGUIを認識してPC全体を操作し実務操作が得意。
2RAGが必要な理由は？
  • A. LLMの計算を速くするため
  • B. LLMが知らない最新情報・社内情報を検索して根拠にし、ハルシネーションを減らすため
  • C. モデルを再学習するため
  • D. 画像を生成するため
正解：B　LLM単体では社内文書や最新情報を知らない。RAGは検索した文書をLLMへ渡して回答の根拠にする。
3Vector Databaseは何を保存し、通常のDBと何が違う？
  • A. 文字列を保存し、完全一致で検索する
  • B. 文章の意味を表すベクトルを保存し、意味（類似度）で検索する
  • C. 画像のみを保存する
  • D. パスワードを保存する
正解：B　Embeddingしたベクトルを保存。通常DBの「一致検索」に対し「同じ意味」を検索できる（例：生成AI⇔大規模言語モデル）。
4EmbeddingとVector Databaseの関係は？
  • A. 無関係
  • B. Embeddingが文章をベクトル化し、そのベクトルをVector Databaseに保存・検索する
  • C. Vector DatabaseがEmbeddingを学習する
  • D. EmbeddingはDBを高速化する技術
正解：B　Embeddingで意味を数値（ベクトル）化し、それをVector Databaseが保存して類似度検索する。
5Function Callingは何のために使う？
  • A. 文章を要約するため
  • B. LLMが必要な機能を選び、外部システムやAPIを呼び出して実際に仕事を実行するため
  • C. モデルを学習するため
  • D. 画面を操作するため
正解：B　LLMが「何を呼ぶか」を判断し、メール送信・予定登録などの外部機能を呼び出す。
6MCPの役割とAPIとの違いは？
  • A. MCPはAIとツールを繋ぐ共通規格、APIは個別接続の通信の仕組み
  • B. MCPとAPIは同じもの
  • C. MCPはモデル学習用のデータ
  • D. APIはAI専用、MCPは開発者専用
正解：A　MCPはAIと多様なToolの接続を標準化する共通規格（AI中心）。APIは個別接続でシステム中心。
7「社内FAQを検索しSlackへ回答を投稿する」業務で使う技術は？
  • A. RAG・Vector Databaseのみ
  • B. Function Calling・MCPのみ
  • C. RAG＋Vector Database（検索）と Function Calling＋MCP（Slack投稿）
  • D. Computer Useのみ
正解：C　FAQ検索はRAG＋Vector Database、Slackへの投稿はFunction Calling＋MCPで実現する。
8マルチエージェントのメリットとして正しいものは？
  • A. システムが単純になる
  • B. コストが必ず下がる
  • C. 専門性が高く、並列処理でき、品質が向上する
  • D. デバッグが簡単になる
正解：C　専門性・並列処理・品質向上・スケール・保守性がメリット。一方で複雑化・通信コスト・デバッグ難はデメリット。
