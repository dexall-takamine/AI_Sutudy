2-1AIは文章を理解しているのか

一言でいうとAIは人間のように「意味」を理解しているのではなく、大量の文章から学んだパターンで次に続く単語を予測している。

人間は「今日は雨だから」と読めば、経験から「傘を持とう」と想像できる。AIに経験・感情・常識はない。代わりに膨大な文章を読み、「今日は雨だから」の後に「傘」が続きやすいことを学んでいる。つまり 統計的に最も自然な続きを選んでいる。

✕ 誤解AIの中には巨大な辞書があり、知識を引いて答えている
○ 正しくは「日本の首都」の後に「東京」が来るパターンを何度も学習しているため、その単語が最も出やすくなっているだけ

LLMの本質は 巨大な次単語予測エンジン。たとえば「私は朝ごはんに」なら内部では確率が計算される。

私は朝ごはんに
パン 42%ご飯 31% / 卵 9% …
「パン」を選ぶ
続きをまた予測これを何十回も繰り返す
図 2-1　予測を繰り返して長い文章が完成する
一文字ずつ書いているわけではない

AIは文字ではなく Token（トークン） という単位で処理する。次節で詳しく扱う。

ここだけ覚える
  • AIは人間のようには理解していない
  • 大量データからパターンを学習している
  • 次に来る単語を予測している

2-2Token と Tokenizer

一言でいうとToken はAIが文章を扱う最小単位。それを作るプログラムが Tokenizer。AIはまず文章を細かく分割する。
私は猫が好きです
私
は
猫
が
好き
です
図 2-2　Tokenizer が文章を Token へ分割する（英語なら I / like / cats / .）

コンピュータは文章をそのまま計算できない。レゴブロックのように小さな単位へ分け、組み立てて処理する。日本語にはスペースがないため、どこで区切るかは Tokenizer が判断する。

Tokenizer はモデルごとに違う

ChatGPT・Claude・Gemini では Tokenizer が異なるため、同じ文章でも Token数が変わる。API料金は文字数ではなく Token数 で決まり、RAG で扱える文章量にも影響する。

ここだけ覚える
  • Token は AI にとっての「単語」のようなもの
  • Tokenizer は Token を作るプログラム（日本語は分割が難しい）
  • Token数は料金・性能・モデルによって変わる

2-3Embedding（埋め込み）

一言でいうとEmbedding は言葉を「意味を持った数字」へ変換する技術。AIが理解できるのは文字ではなく数字だけ。

「猫」という文字は AI には読めない。そこで 猫 → [0.82, -0.15, 0.64, …] のように数百〜数千個の数字（ベクトル）へ変換する。これが Embedding。

  • 意味の地図（Embedding空間）
    • 動物
      • 犬・猫・狼 ── 近くに配置
    • 乗り物
      • 車・電車・飛行機 ── 別の場所に配置
図 2-3　意味が近い言葉ほど数字（位置）も近くなる
✕ 誤解Embedding は翻訳のことだ
○ 正しくは意味を数字で表現する技術。だからAIは「犬は猫に近い」と分かる。社内検索（RAG）の中核技術でもある
ここだけ覚える
  • AIは文字ではなく数字を読む
  • Embedding は意味を数字へ変換する
  • 意味が近い言葉ほど数字も近くなる

2-4Positional Encoding（位置情報）

一言でいうとPositional Encoding は「単語が文章のどこにあるか」をAIへ教える仕組み。Transformer は単語を並列に処理するため、そのままでは順番が分からない。

「私は犬が好きです」と「犬が私は好きです」── 位置情報がなければ、AIにはどちらも同じ単語の集まりに見えてしまう。本のページ番号や電車の座席番号と同じで、番号があるから順番に並べ直せる。

猫Token
(0.32, 0.71, -0.52 …)Embedding＝意味
＋ Position 3位置＝順番
Transformer へ「3番目の猫」と分かる
図 2-4　Transformer が読むのは「意味 ＋ 位置」
なぜ位置情報が要るのか

昔の RNN は一語ずつ順番に読むので順序は自然に分かった。Transformer は全部を同時に読む（高速・長文に強い）代わりに、位置を別途追加する必要がある。位置情報は「どこにあるか」を教えるだけで、意味は Transformer 全体で理解する。

ここだけ覚える
  • Transformer は単語の順番が分からない
  • Positional Encoding で位置を追加する
  • Embedding は「意味」、Position は「順番」

2-5Transformer とは

一言でいうとTransformer は現在の生成AIの頭脳となるアーキテクチャ（設計図）。ChatGPT・Claude・Gemini・Llama・DeepSeek・Qwen など、ほぼすべてのLLMの基礎。

2017年、Googleの研究者が論文 「Attention Is All You Need」 で Transformer を発表し、生成AIの性能は飛躍的に向上した。Transformer 以前の RNN は文章を順番に読むため、長文だと前半を忘れる 長期依存問題 を抱えていた。

RNN（昔のAI）Transformer
読み方順番に1語ずつ全体をまとめて
速度遅い高速（GPUで並列）
長文前半を忘れやすい全体を見られる
Token → Embedding → Positional Encoding意味と位置を準備
Self-Attention（重要な単語を見つける）×　Multi-Head で多視点に
Feed Forward（情報を整理）
これを数十〜百層も繰り返す → Decoder で回答生成
図 2-5　Transformer の内部構造（GPTでは数十〜百以上の層が重なる）
✕ 誤解Transformer ＝ ChatGPT
○ 正しくはTransformer はAIの設計図（アーキテクチャ）。ChatGPT はそれを利用したサービス
ここだけ覚える
  • Transformer は現在のLLMの基盤技術
  • 2017年 Google「Attention Is All You Need」から生まれた
  • 文章全体を見ながら高速に処理できる

2-6Self-Attention / Multi-Head Attention

一言でいうとSelf-Attention は「文章の中でどの単語が重要かをAI自身が判断する」仕組み。Transformer が高性能になった最大の理由。

「太郎は花子に本を貸しました。彼女は喜びました。」── 人間はすぐ「彼女＝花子」と分かる。AIは前の文へ目を戻すように、単語同士の 関係性 を数値で計算する。Self（自分自身） とは「同じ文章の中だけを見る」という意味。

好き
私 20% / 犬 60% / です 10% …全単語との関係を計算
「好き」は「犬」と関係が強い
図 2-6a　「私は犬が好きです」── 全員が全員を見て重要度を計算する

同じ「アップル」でも、前後を見れば「iPhoneを発売した→Apple社」「食べた→リンゴ」と意味を判断できる。これが 文脈理解。さらに 1000文字前の「田中さん」も必要なら見に行けるので長文に強い。

Multi-Head Attention は、この Self-Attention を複数の視点で同時に動かす仕組み。同じ資料を営業・経理・法務が別の観点で読むのと同じ。

Head 1：誰？

佐藤さん

Head 2：いつ？

昨日

Head 3：どこ？

東京駅

Head 4：何をした？

昼食を食べた

図 2-6b　「佐藤さんは昨日東京駅で田中さんと昼食を食べた」を複数 Head が多角的に分析し、最後に結合する
弱点：計算量が大きい

100単語なら約100×100＝1万回、1000単語なら約100万回の比較が必要。長文ほどGPU・メモリを大量に消費する。Head が増えるほど計算量も増える。

ここだけ覚える
  • Self-Attention は「重要な単語はどれか」をAI自身が判断する
  • 単語同士の関係を数値として計算する（＝文脈理解の正体）
  • Multi-Head Attention は複数の視点で同時に文章を見る

2-7Feed Forward と Decoder

一言でいうとFeed Forward Network は Attention で集めた情報を整理する係。Decoder は次の Token を1つずつ生成して文章を書く係。

Attention が「情報を集める（Googleで調べる）」なら、FFN は「集めた情報を予算・日程・優先順位で整理する」役割。Transformer は Attention → FFN を何十回も繰り返し、少しずつ理解を深める。

最後に Decoder が回答を書く。「日本の首都は？」→「東京」→「です」→「。」と Token を1つずつ追加していく。これを 自己回帰生成（Autoregressive Generation） と呼ぶ。スマホの予測変換に似ているが、何兆もの学習データをもとに予測している点が違う。

東京
東京は
東京は日本の
東京は日本の首都
…<END> で終了
図 2-7　Decoder は Token を1つずつ追加し、特殊な <END> Token で回答を終える
✕ 誤解AIは全文を考えてから書いている
○ 正しくはToken を1つずつ予測しながら書いている。途中で間違えるとその後も誤った方向へ進む ── これがハルシネーションの原因の一つ
ここだけ覚える
  • FFN は Attention で集めた情報を整理する
  • Transformer は Attention と FFN を何度も繰り返す
  • Decoder は Token を1つずつ生成して文章を書く

2-8Sampling・Temperature・Top-p

一言でいうとこれらは「次の Token をどう選ぶか」を決める仕組み。毎回1位だけ選ぶと回答が単調になるため、少しランダム性を持たせる。

AIは候補と確率を持っている（例：東京 96% / 大阪 2% / 京都 1% …）。毎回1位だけ選ぶと「面白い物語を書いて」が毎回ほぼ同じになる。Sampling は、たまに違う候補も選ぶ仕組み ── 昼食をたまに寿司にするのと同じ。だから同じ質問でも毎回少し回答が変わる。

パラメータ役割挙動
SamplingTokenの選び方確率に従い、少しランダムに選ぶ
Temperatureランダムさの強さ低い＝正確・安定／高い＝創造的・不安定
Top-p候補の数を絞る有力候補だけ残し、変な単語を捨てる
次Token候補100個
Top-p上位だけ残す
Temperatureランダムさ調整
Sampling で Token決定
図 2-8　実際は Top-p で絞り → Temperature で調整 → Sampling で選ぶ（就活で上位10社に絞り、その中から自由に選ぶイメージ）

Temperature の目安（用途別）。低いほど「教科書」、高いほど「アイデアマン」。

用途Temperature
契約書要約・FAQ・翻訳・プログラム生成0 〜 0.3
ブログ・通常の会話0.7 〜 1.0
企画・キャッチコピー1.0 前後
小説・創作1.2 〜 1.5

低 Temperature

  • 正確・安定・再現性が高い
  • 事実確認・要約・コードに向く
  • 創造性は低い

高 Temperature

  • 創造的・アイデア豊富
  • 物語・企画に向く
  • ハルシネーション（誤情報）が増える
ChatGPT画面では設定できる？

通常の ChatGPT 画面では Temperature・Top-p を直接変更できず、OpenAI 側が用途に合わせた値を設定している。API を使う場合は開発者が temperature top_p を調整できる。Temperature を上げても知識量は増えず、創造性が上がるだけ。

ここだけ覚える
  • Sampling は Token の選び方（毎回少し違う回答になる理由）
  • Temperature はランダムさ ── 低いほど正確、高いほど創造的
  • Top-p は候補を絞る ── 両方で「正確性」と「創造性」のバランスを取る

2-9Context Window（コンテキストウィンドウ）

一言でいうとContext Window はAIが一度に記憶して処理できる情報量。AIの「作業用メモリ」で、Token数で決まる。

1000ページ進んだ本の最初の一文を正確に覚えていられないように、AIも一度に扱える量に限界がある。質問・会話履歴・PDF・RAGの検索結果・AIの回答 ── これらすべての合計がこの枠に収まる必要がある。

会話履歴 ＋ 質問 ＋ 資料 ＋ RAG検索結果 ＋ AIの回答
これらの合計が Context Window 内に収まる（例：100万Token対応モデル）
枠を超えると古い情報から順に見えなくなる
図 2-9　Context Window を超えると、古い会話から忘れていく

長い会話で「さっき言ったこと覚えてる？」が通じなくなるのは、古い情報が枠から外れるため。大きいほど 500ページのPDFや10時間分の議事録もまとめて扱え、RAG にもたくさん渡せる。ただし良いことばかりではない。

大きいほど良いわけではない

Token数が増えるほど 計算量・料金・処理時間 が増える。実務では「100ページ全部」ではなく「必要な5ページだけ」を渡す方が高速で正確。だから RAG は検索してから AI へ渡している。

✕ 誤解ChatGPT は全部覚えている／長いほど賢い
○ 正しくは覚えているのは Context Window 内だけ。長いのは「扱える情報が増える」だけで、知識量が増えるわけではない
ここだけ覚える
  • Context Window は AI の作業用メモリ（Token数で決まる）
  • 長いPDFを読める理由・会話を忘れる理由はこれ
  • 大きいほど計算量・料金・時間も増える。RAG でも重要
